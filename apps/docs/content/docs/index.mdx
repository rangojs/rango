Rango (`@rangojs/router`) is a React Server Components router built on Vite. It is Django-inspired: routes are expressed in one tree, every route carries a name, and URLs are built from names — never hand-assembled from strings. Apps deploy to Cloudflare Workers or Vercel.

The stance underneath everything: **explicit over implicit, correct by default, and the source is the source of truth.** Every behavior is a stated contract you can read, test against, and grep for.

## The shape of Rango

- **Routes are expressed, not configured.** The `urls()` tree shows where every route, layout, loader, and cache lives. No file-system convention, no hunting across `page.tsx` / `layout.tsx` / `route.ts` siblings.
- **Two freshness axes, orthogonal.** "Is this stored value still good?" is answered by `cache()` and `"use cache"`. "Should this segment re-render right now?" is answered by `revalidate()`. Other frameworks answer both with one word; Rango never conflates them.
- **Loaders are the live lane.** A loader resolves fresh on every request — even inside a cached render — and streams, so data latency overlaps first paint instead of blocking it.
- **Type-safe end to end.** Route names, params, search schemas, loader return types, and `reverse()` / `href()` are checked at compile time against generated route maps.
- **Semantics are a contract, not folklore.** Dev and production resolve every request through the same route trie, and JS and no-JS produce the same middleware effects, cookies, and rendered state — both pinned by a semantic matrix test suite.

## A taste

One tree, both axes visible — structure (`layout` / `path`) versus config (everything else), freshness (`cache`) versus client-update (`revalidate`):

```tsx
export const urlpatterns = urls(
  ({ path, layout, loader, loading, cache, revalidate }) => [
    layout(<ShopLayout />, () => [
      loader(CartLoader, () => [
        revalidate((ctx) => ctx.isAction(CartActions) || undefined),
      ]),
      path("/shop/:slug", ProductPage, { name: "product" }, () => [
        loader(ProductLoader, () => [cache({ ttl: 60 })]),
        loading(<ProductSkeleton />),
      ]),
    ]),
  ],
);
```

From this one file you can answer the three questions that usually require a codebase tour: what URLs exist and who owns them, can I trust this reference without leaving the call site, and what re-renders after this action.

## Status

The router is experimental. The semantics are pinned and tested, and the API is converging, but pre-1.0 means pre-1.0.
