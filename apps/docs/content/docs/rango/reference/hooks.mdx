Import every hook on this page from `@rangojs/router/client`. The root `@rangojs/router` entry is for server/RSC APIs and shared types. The hooks are client APIs: call them from `"use client"` components. Two exceptions to the import rule: `invalidateClientCache()` is exported only from the root entry, and `createLocationState()` is exported from both. The theme hook, `useTheme()`, lives in `@rangojs/router/theme` (see [Theme](/docs/rango/guides/theme)).

Data fetching happens in server-side [loaders](/docs/rango/features/loaders). Client hooks like `useLoader()` only consume what a loader resolved.

## Summary

| Hook                      | Purpose                                       | Returns                                                                         |
| ------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------- |
| `useNavigation()`         | Reactive navigation state                     | state, location, pendingUrl, isStreaming                                        |
| `useRouter()`             | Stable router actions                         | push, replace, refresh, prefetch, back, forward                                 |
| `useSegments()`           | URL path and segment IDs                      | path, segmentIds, location                                                      |
| `useLinkStatus()`         | Link pending state                            | `{ pending }`                                                                   |
| `useLoader()`             | Loader data (strict)                          | data, isLoading, error, load, refetch                                           |
| `useFetchLoader()`        | Loader with on-demand fetch                   | data, load, isLoading, error, refetch                                           |
| `useRefreshLoaders()`     | Refresh cross-loader group(s)                 | `(groups: string \| string[]) => Promise<void>`                                 |
| `useParams()`             | Route params                                  | `Readonly<T>` (default `Record<string, string \| undefined>`) or selected value |
| `usePathname()`           | Current pathname                              | `string`                                                                        |
| `useSearchParams()`       | Read and write URL search params              | `[ReadonlyURLSearchParams, SetSearchParams]`                                    |
| `useHref()`               | Mount-aware href                              | `(path) => string`                                                              |
| `useMount()`              | Current `include()` mount path                | `string`                                                                        |
| `useReverse(routes)`      | Local reverse for imported routes             | `(name, params?, search?) => string`                                            |

| `useNonce()`              | CSP nonce during SSR                          | `string \| undefined`                                                           |
| `invalidateClientCache()` | Force client caches to miss (function)        | `void`                                                                          |

## Navigation

### useNavigation()

Reactive navigation state, with no actions. The selector form re-renders only when the selected value changes.

```tsx
"use client";
import { useNavigation } from "@rangojs/router/client";

function NavIndicator() {
  const nav = useNavigation();
  // nav.state: 'idle' | 'loading'    nav.isStreaming: boolean
  // nav.location: current URL        nav.pendingUrl: target URL or null
  return nav.state === "loading" ? <Spinner /> : null;
}
const isLoading = useNavigation((nav) => nav.state === "loading"); // selector
```

A link click, `router.push()` and a Back/Forward that has to fetch its entry report a pending navigation the same way. `state === "loading"` and `pendingUrl` (the URL being fetched) cover the network wait. `isStreaming` is true from the start of the request until the response's stream ends, so it also covers the part where the response has arrived and React still holds the page being left behind a loader that is streaming; use it for a progress indicator that should last until the new page is complete. `location` is the page on screen while the request is out, and moves when the response arrives. A Back/Forward served from the client's history cache restores its page in one commit and reports no pending state.

### useRouter()

Stable router actions. The returned object never changes identity, so components using it do not re-render on navigation. Call its methods from event handlers or effects.

```tsx
"use client";
import { useRouter } from "@rangojs/router/client";

const router = useRouter();
router.push("/products"); // navigate (adds a history entry)
router.replace("/login", { scroll: false }); // navigate (replaces the entry)
router.refresh(); // re-fetch the current route's server data
router.prefetch("/dashboard"); // prefetch for faster navigation
router.back(); // history.back()
router.forward(); // history.forward()
```

| Method                   | Behavior                                                                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `push(url, options?)`    | Navigate and add a history entry. Returns a promise.                                                            |
| `replace(url, options?)` | Navigate and replace the current history entry. Returns a promise.                                              |
| `refresh()`              | Re-fetch the current route's server data, keeping client state. Returns a promise.                              |
| `prefetch(url, opts?)`   | Prefetch a target. `{ key: ":source" }` scopes the entry to the source page (parity with `<Link prefetchKey>`). |
| `back()`                 | `history.back()`. On the first entry of the session it replaces to the app root instead of leaving the app.     |
| `forward()`              | `history.forward()`.                                                                                            |

`push` and `replace` accept `scroll` (`false` keeps the current scroll position), `revalidate` (default `true`), `transition` (`false` skips the route's `transition()` for this navigation), and `state` (location state, see [useLocationState](#uselocationstatedefinition)). A path starting with `/` is app-absolute and gets the router `basename` prefixed. A relative path (`"cart"`, `"./cart"`) resolves against the current `include()` mount, so `router.push("cart")` inside `include("/shop", ...)` navigates to `/shop/cart`.

`revalidate: false` skips the RSC server fetch for same-pathname navigations (search param or hash changes): the URL updates and hooks re-render, but server components stay as they are. It is silently ignored when the pathname changes. It is also available as `<Link revalidate={false}>`, and plain `<a>` tags opt in with `data-revalidate="false"`.

```tsx
router.push("/products?color=blue", { revalidate: false });
```

`transition: false` presents one navigation without the route's `transition()`: the commit is urgent (the `loading()` skeleton streams) and no view transition runs, the same result as a [`transition({ when })`](/docs/rango/guides/view-transitions#conditional-transitions-with-when) predicate returning `false`, and no predicate is called. It is also available as `<Link transition={false}>` and `data-transition="false"` on a plain `<a>`. Back/forward, actions and revalidation are unaffected.

```tsx
router.push("/photos/2", { transition: false });
```

### useSegments()

The current URL path and matched route segments. Supports the selector form.

```tsx
"use client";
import { useSegments } from "@rangojs/router/client";

const { path, segmentIds, location } = useSegments();
// path: ["shop", "products", "123"] (split on "/")
// segmentIds: layouts and routes only; opaque internal short-codes, not route names
// location: URL object

const isShopRoute = useSegments((s) => s.path[0] === "shop"); // selector
```

The selector is applied when the router store changes (a navigation or new handle data), as with `useNavigation` and `useAction`. A new selector function on a re-render takes effect at the next change; to derive from a prop, call `useSegments()` and derive in render.

### useLinkStatus()

Pending state inside a `<Link>`: `pending` is `true` while a navigation to that link's `to` is in flight. The component calling it must render inside a `Link`.

```tsx
"use client";
import { Link, useLinkStatus } from "@rangojs/router/client";

function LoadingIndicator() {
  const { pending } = useLinkStatus();
  return pending ? <Spinner /> : null;
}
// <Link to="/dashboard">Dashboard <LoadingIndicator /></Link>
```

## Data

### useLoader(loader, options?)

Strict loader access: once the component renders, `data` is present. It throws if the loader is not in context, so the loader must be registered on an active route with the `loader()` helper. Loaders can also be passed as props from server to client components (`loader: typeof ProductLoader` infers the data type).

```tsx
"use client";
import { useLoader } from "@rangojs/router/client";
import { ProductLoader } from "../loaders/product";

function ProductPrice() {
  const { data, isLoading } = useLoader(ProductLoader);
  return <span style={{ opacity: isLoading ? 0.5 : 1 }}>${data.price}</span>;
}
```

Loaders stream, and `useLoader()` suspends. A first read whose data has not streamed in yet suspends to the nearest `<Suspense>` boundary or the route's `loading()`; it does not render with `isLoading: true`. `isLoading` covers later work: `load()` and `refetch`, key and group refreshes, and a held navigation (a `transition()` or same-structure navigation that keeps the old data on screen while the loader re-runs).

`load()` and `refetch` require a fetchable loader (`createLoader(fn, true)` or `createLoader(fn, { middleware })`). A plain `load()` (no options) on a route-registered loader broadcasts its result to every component reading the same loader: layout, page, and parallel-slot reads converge on the new value. `isLoading` and `error` share the same scope.

Options: `key` (partitions the shared refresh store), `refreshGroup` (one name or an array, for `useRefreshLoaders()`), and `throwOnError`.

### useFetchLoader(loader, options?)

Loader access with on-demand fetching: `data` is `T | undefined` until `load()` resolves. The loader must be fetchable: `createLoader(fn, true)`, or `createLoader(fn, { middleware })` to run per-loader middleware on client fetches.

```tsx
"use client";
import { useFetchLoader } from "@rangojs/router/client";
import { SearchLoader } from "../loaders/search";

const { data, load, isLoading, error } = useFetchLoader(SearchLoader);
await load({ params: { query } }); // refetch is an alias for load
```

- `load({ params })`, `load({ method: "POST", body })`, and any `load()` on a loader not registered on the current route stay **local** (per-hook state).
- A `key` option partitions the shared refresh store: only readers with the same `key` refresh together. It also lets parameterized GETs and unregistered loaders share one result. Mutations stay local even with a key.
- Body encoding switches automatically: a `FormData` body is sent as `multipart/form-data` (the server reads `ctx.formData`); anything else is JSON-serialized (the server reads `ctx.body`).
- Client-supplied `params` land in the loader's `ctx.params`. `ctx.routeParams` always holds the server-trusted values from URL matching, so use it for authorization checks.

### useRefreshLoaders()

Refreshes **different** loaders together. Tag reads with a shared `refreshGroup` (one name or an array); the hook takes no argument and returns the trigger function.

```tsx
"use client";
import { useLoader, useRefreshLoaders } from "@rangojs/router/client";

const { data } = useLoader(OrdersLoader, {
  key: userId,
  refreshGroup: ["account", "orders"],
});

const refresh = useRefreshLoaders();
await refresh("account"); // every mounted member of the group
await refresh(["account", "orders"]); // union; shared members are fetched once
```

`refresh(groups)` re-runs each member with a plain GET (no params, no body), resolves when all settle, and rejects with an `AggregateError` if any fail. It never render-throws, so handle failures at the await site. Keep parameterized loaders on the single-loader `key` instead.

## URLs and params

### useParams()

Merged params from all matched route segments as a `Readonly<T>` map. The default `T` is `Record<string, string | undefined>`, because absent optional params are omitted, so guard them. Updates on navigation commit, not during a pending navigation. Supports the selector form.

```tsx
"use client";
import { useParams } from "@rangojs/router/client";

// Route: /product/:productId
const { productId } = useParams<{ productId: string }>();
const id = useParams((p) => p.productId); // selector
```

### usePathname()

The pathname of the page on screen, without search params or hash. It changes when a navigation's destination commits (see [When the URL hooks change](#when-the-url-hooks-change)).

```tsx
"use client";
import { usePathname } from "@rangojs/router/client";

const pathname = usePathname(); // "/product/123"
```

### useSearchParams()

Reads and writes the current URL search params. It returns a tuple, like React Router's hook:

```tsx
"use client";
import { useSearchParams } from "@rangojs/router/client";

const [searchParams, setSearchParams] = useSearchParams();
const query = searchParams.get("q");

setSearchParams({ q: "kettle", page: 2 }); // replace the whole search string
setSearchParams((prev) => {
  prev.set("page", "3"); // merge: prev is a mutable copy of the current params
  return prev;
});
setSearchParams(
  { view: "grid" },
  { replace: true, scroll: false, revalidate: false },
);
```

The first element is a `ReadonlyURLSearchParams` (`URLSearchParams` without mutation methods) from the committed location. During document SSR it carries the request's search string, so SSR and hydration agree.

The setter **replaces** the whole search string and navigates to the current pathname with the new params, so route loaders re-evaluate per their `revalidate()` rules. It accepts a string, a `URLSearchParams`, a record (numbers and booleans are stringified, arrays append one entry per element, `null` and `undefined` are skipped), or a function of the current params. The hash is dropped. Options: `replace` (default `false`), `scroll` (default `true`), and `revalidate` (default `true`; `false` skips the server fetch).

### When the URL hooks change

`usePathname()`, `useSearchParams()` and `useParams()` describe the page on screen. They change in the commit that shows a navigation's destination, not when the navigation starts, for Back/Forward as for a link click or `router.push()`.

| Navigation                                        | The hooks change                                                           |
| ------------------------------------------------- | -------------------------------------------------------------------------- |
| `<Link>`, `router.push()` / `router.replace()`    | when the destination commits                                               |
| Back/Forward, entry in the client's history cache | with the restored page, in one commit                                      |
| Back/Forward, entry fetched again                 | when the fetched page commits; until then the page being left is on screen |
| a Back/Forward whose fetch fails                  | with the error boundary: they report the entry the browser is on           |
| `router.push(url, { revalidate: false })`         | at once: nothing is fetched and the page stays                             |
| inside an optimistic `clientUrls()` destination   | at the click, for that branch only                                         |

On Back/Forward the browser changes the address bar and `history.state` before it tells the router. When the entry has to be fetched, the page being left stays on screen for the wait and the hooks keep reporting its URL, so **for that wait the hooks disagree with the address bar**: `window.location` is already the destination's. An active-link highlight, a breadcrumb or a filter panel derived from the hooks therefore stays in step with the content next to it. For anything you render, read the hooks, not `window.location`; for pending UI, read [`useNavigation()`](#usenavigation). `setSearchParams((prev) => ...)` called during the wait builds on the search of the page on screen.

One gap ([#1046](https://github.com/rangojs/rango/issues/1046)): a component that first mounts in the page being left after the navigation's response has arrived, while React still holds the destination behind a loader or a `transition()`, reads the destination's URL and params from these hooks. Components that were already mounted are not affected. It applies to a push and to Back/Forward alike.

### useHref()

A mount-aware href function that prepends the current `include()` mount prefix. Use the bare `href()` function for absolute paths outside the current mount. The returned function is stable within a mount.

```tsx
"use client";
import { href, useHref, Link } from "@rangojs/router/client";

// Inside include("/shop", shopPatterns)
const localHref = useHref();
<Link to={localHref("/cart")}>Cart</Link>; // "/shop/cart"
<Link to={href("/about")}>About</Link>; // "/about", not prefixed
```

### useMount()

The current `include()` mount path: `"/shop"` inside `include("/shop", ...)`, `"/"` at the root. It reads `MountContext`, which `include()` sets automatically.

```tsx
"use client";
import { useMount } from "@rangojs/router/client";

const mount = useMount();
```

### useReverse(routes)

A typed, mount-aware local reverse for the `routes` map imported from a `urls()` module's generated `.gen.ts`. It fills params from `useParams()` (explicit params override), and the leading dot on names is optional. The CLI writes per-module `*.gen.ts` files; the Vite plugin does not, so run `rango generate` when a module's routes change. See the [CLI reference](/docs/rango/reference/cli).

```tsx
"use client";
import { Link, useReverse } from "@rangojs/router/client";
import { routes as blogRoutes } from "../urls/blog.gen.js";

const reverse = useReverse(blogRoutes);
<Link to={reverse("post", { postId: "hello" })}>Post</Link>;
```

`ctx.reverse()` is server-only. See [Named Routes & Links](/docs/rango/features/named-routes) for the full URL generation surface.

## Handles and actions

### useHandle(handle, selector?)

Accumulated handle data from route segments. Handlers and loaders write it with `ctx.use(Handle)`, and `useHandle()` re-renders on every update. Handles can be passed as props from server to client components (`handle: typeof Breadcrumbs` infers the full `Handle<T>` type); RSC serialization strips the `collect` function, which `useHandle()` recovers from the module-level registry.

```tsx
"use client";
import { useHandle, Breadcrumbs } from "@rangojs/router/client";

const crumbs = useHandle(Breadcrumbs); // array of { label, href } from layouts/routes
const lastCrumb = useHandle(Breadcrumbs, (data) => data.at(-1));
```

### useAction(action, selector?)

Tracks the lifecycle of a server action wherever on the page it was invoked. If the same action fires several times, the hook reports the latest call. For the full action surface, including `useActionState` and `useOptimistic`, see [Server Actions](/docs/rango/guides/server-actions).

```tsx
"use client";
import { useAction } from "@rangojs/router/client";
import { addToCart } from "../actions/cart";

const { state, error, result } = useAction(addToCart);
// state: 'idle' | 'loading' | 'streaming'; also actionId and payload (the call's arguments)

// Match by export name (a suffix match; ambiguous if two "use server" files export the same name)
const isAdding = useAction("addToCart", (s) => s.state === "loading");
```

Pass an action imported directly into the client component, or its export name as a string. An action received as a prop from a server component has lost the metadata `useAction` needs and throws, so use the string form there.

## State and cache control

### useLocationState(definition)

Type-safe history state. Define a slot with `createLocationState<T>()` (the Vite plugin injects its key; in a unit test use `withLocationStateKey()` from `@rangojs/router/testing`); the hook returns `T | undefined`.

```tsx
"use client";
import {
  useLocationState,
  createLocationState,
  Link,
} from "@rangojs/router/client";

export const ProductState = createLocationState<{
  name: string;
  price: number;
}>();

const state = useLocationState(ProductState); // { name; price } | undefined

<Link to="/product/123" state={[ProductState({ name: "Widget", price: 99 })]}>
  View
</Link>;
```

A reader gets an entry's state in the same commit as that entry's page. While a navigation is pending (its loader still streaming, a `transition()` holding the page), the content on screen keeps the state of the entry being left, including for a reader that mounts during the wait; back/forward restores an entry's state together with its page. Inside an optimistically presented `clientUrls()` destination the hook returns the state the navigation carries, before the server has answered. A navigation that carries no state re-renders no reader; a value keeps its identity when a navigation passes the reader's own value forward or a server action changes another slot.

The URL hooks follow the same rule for a component that is mounted across the navigation, on back/forward too (see [When the URL hooks change](#when-the-url-hooks-change)). One difference remains ([#1046](https://github.com/rangojs/rango/issues/1046)): a component that first mounts in the page being left, after the response arrived and while React still holds the destination, reads its own entry's state from `useLocationState` and the destination's URL and params from `usePathname()`, `useSearchParams()` and `useParams()`.

`useLocationState<T>()` with no definition reads plain, untyped state. The same `state` option exists on `router.push()` and `router.replace()`, typed `HistoryState`: typed entries in an array (`[ProductState(value)]`) or plain structured-clone-safe data (`PlainHistoryState`). An entry passed without the array (`state: ProductState(value)`), a definition passed without calling it (`state: [ProductState]`), or an array mixing entries with plain values is a compile error, and in development a runtime error for untyped callers.

Plain state is checked at the top level only: functions, symbols, `Promise`, `WeakMap`, `WeakSet`, and `unknown` values are rejected, and array, `Map`, and `Set` elements are checked the same way, but plain object members are not. A function or React element inside a plain object, or a top-level React element or DOM node, still compiles and throws `DataCloneError` when the history entry is written. A typed `createLocationState<T>()` definition checks `T` all the way down.

`createLocationState<T>()` rejects types that cannot survive `history.state`'s structured clone (functions, symbols, React/RSC content, `unknown` fields). The compile error names the failing field and the reason, for example `LocationStateUnsafe<"...", "items[].info.values">` for an `unknown` field inside each element of `items`.

`createLocationState<T>({ flash: true })` makes read-once flash state that is cleared from the history entry after it is read, so back/forward and a reload will not show it again. It stays on screen until the next navigation commits. Set it from the server with `redirect(url, { state: [...] })` or `ctx.setLocationState(...)`.

Static access: `.read()` returns a snapshot (`undefined` during SSR, so call it post-mount, not during the initial render). `.write()` and `.delete()` mutate `history.state` via `replaceState`, are client-only (they throw on the server), and do not change what `useLocationState` readers show, mounted or mounting later: readers get the written value when the entry is next restored (back/forward to it, or a reload). `.read(location)` reads the slot from any `{ state }` snapshot instead of the current entry, such as a `transition({ when })` context's `from` / `to`; it works without `window` and never clears flash state.

### invalidateClientCache()

Not a hook: a plain function from the root entry, usable in module-level callbacks. It forces the client's caches to miss after a mutation the router can't see (a REST call, a WebSocket push, a login). Export conditions pick the implementation. In client code it marks the caches stale immediately; from a handler, server component, middleware, loader, or action it writes a rotated state `Set-Cookie`. Server actions already invalidate the client caches, so you don't call it after one.

```ts
import { invalidateClientCache } from "@rangojs/router";

socket.on("catalog-updated", () => invalidateClientCache());
```

## Outlets

### useOutlet()

Returns `OutletState`, not a bare React node:

```ts
interface OutletState {
  readonly content: ReactNode;
  readonly pending: boolean;
}
```

`content` is the child outlet content. `pending` is the descendant presentation signal for hydrated `clientUrls()` navigation: it becomes `true` when the browser locally matches a client route beneath that layout — a different route, or a param or search change on the same route (the only progress signal for a held filter or tab navigation) — and clears when the canonical partial Flight navigation commits or otherwise settles. It is `false` during SSR and for ordinary server routes, prefetches, generic Suspense, and unrelated actions. Use `useNavigation()`, `useLinkStatus()`, or loader state for those other pending scopes.

The companion components `Outlet` and `ParallelOutlet` (`<ParallelOutlet name="@sidebar" />`) render child and named-slot content in layouts. See [Parallel Routes](/docs/rango/guides/parallel-routes).

```tsx
"use client";
import { useOutlet } from "@rangojs/router/client";

function CatalogLayout() {
  const { content, pending } = useOutlet();
  return content ? (
    <div className="with-content" aria-busy={pending}>
      {content}
    </div>
  ) : (
    <Empty />
  );
}
```

`<Outlet />` is enough when a layout only needs to render its child.

## Scroll and nonce

### useScrollRestoration(options?)

Turns on saved scroll positions: they are stored in `sessionStorage` per history entry and restored on back/forward navigation. Scrolling to the top on a new navigation and to a hash target work without it. The default document already renders the equivalent `<Html.ScrollRestoration />`. With a custom document, call it once there or in the root layout, or render `<Html.ScrollRestoration />`. Without it (a custom document that renders neither), back/forward scroll is left to the browser's own restoration, and the router does not scroll on back/forward.

```tsx
"use client";
import { useScrollRestoration } from "@rangojs/router/client";

function AppShell({ children }: { children: React.ReactNode }) {
  useScrollRestoration();
  return <>{children}</>;
}
```

`getKey` changes what a saved position is keyed by. The default is the unique history entry; `(location) => location.pathname` restores by path. Pass a stable function (module-level or memoized), because a new identity re-initializes restoration and discards unsaved positions. A function can't cross from a server component to a client one, so pass `getKey` from a client component, such as your document. With the default document, pass your own document to set `getKey`: a second instance only warns (`[Scroll] Already initialized`).

### useNonce()

Returns the request's CSP nonce during SSR and `undefined` in the browser. Use it in client components that render their own `<script>` or `<style>` into the document head (analytics, tag managers), so the nonce lands in the SSR HTML. The nonce comes from the router's [`nonce` option](/docs/rango/reference/create-router#nonce).

```tsx
"use client";
import { useNonce } from "@rangojs/router/client";

function Analytics() {
  const nonce = useNonce();
  return <script nonce={nonce} src="/analytics.js" async />;
}
```
