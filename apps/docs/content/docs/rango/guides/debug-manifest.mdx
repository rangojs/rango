A path resolves to the wrong handler, a layout isn't wrapping its children, or an intercept never fires. The debug manifest shows you the route tree Rango actually built from your `urls()` — parent relationships, shortCodes, and which entries carry loaders, middleware, error boundaries, parallel slots, or intercepts — so you can verify structure instead of guessing.

It is a development aid; the diff helpers shown below are internal and may change between releases.

## Programmatic access

The router returned by `createRouter()` has an async `debugManifest()` method that returns a summarized `{ routes, layouts, totalRoutes, totalLayouts }` shape, typed as `SerializedManifest` (`import type { SerializedManifest } from "@rangojs/router"`):

```ts
import { router } from "./router.js";

// Development only
if (process.env.NODE_ENV !== "production") {
  const manifest = await router.debugManifest();
  console.log(JSON.stringify(manifest, null, 2));
}
```

Run it on the server side (for example from a dev-only route handler), since it evaluates your `urls()` tree.

`include()` groups are not expanded. They are lazy: the router evaluates one on the first request that matches its prefix, and `debugManifest()` does not evaluate them. It lists the routes and layouts declared directly in each `.routes()` / `urls` mount, so the routes inside an included group are missing from `routes` and `totalRoutes`. For their names and patterns, read the generated `*.named-routes.gen.ts` file, which lists every route including those in `include()` groups.

Every entry has the same fields; `pattern` is present on routes only. Cache boundaries are listed under `layouts` with `type: "cache"`. A typical result (values are illustrative):

```jsonc
{
  "routes": {
    "home.index": {
      "id": "debug.M0.$root.$route.0.home.index",
      "shortCode": "M0L0R0",
      "type": "route",
      "parentShortCode": "M0L0",
      "pattern": "/",
      "hasLoader": false,
      "hasMiddleware": false,
      "hasErrorBoundary": false,
      "parallelCount": 0,
      "interceptCount": 0,
    },
  },
  "layouts": {
    "debug.M0.$root": {
      "id": "debug.M0.$root",
      "shortCode": "M0L0",
      "type": "layout",
      "parentShortCode": null,
      "hasLoader": false,
      "hasMiddleware": false,
      "hasErrorBoundary": false,
      "parallelCount": 0,
      "interceptCount": 0,
    },
  },
  "totalRoutes": 45,
  "totalLayouts": 18,
}
```

## Reading shortCodes

A shortCode is the parent's shortCode plus one segment per level:

| Prefix | Meaning                                                                 |
| ------ | ----------------------------------------------------------------------- |
| **M**  | Mount index (`.routes()` / `urls` registrations and `include()` mounts) |
| **L**  | Layout (the router adds a root layout, `M<n>L0`)                        |
| **C**  | Cache boundary                                                          |
| **R**  | Route                                                                   |
| **P**  | Parallel slot                                                           |
| **I**  | `include()` scope token, so included routes never collide with siblings |

Example: `M0L0L1C0R0` = Mount 0 → Root Layout → Nested Layout → Cache → Route. At runtime, a route from an `include()` placed under the root layout gets a shortCode such as `M0L0I0R0`.

## What to verify

1. **Correct hierarchy**: the shortCode reflects nesting — `M0L0L1R0` for a route in a nested layout, not `M0L0R0`.
2. **Parents**: only a mount's root layout (`M<n>L0`) has `parentShortCode: null`.
3. **Loaders attached**: `hasLoader: true` on routes and layouts that declare `loader()`.
4. **Intercepts registered**: `interceptCount > 0` where you declared `intercept()` for modal/overlay patterns (see [Intercepting Routes](/docs/rango/guides/intercepting-routes)).
5. **Slots**: `parallelCount` matches the number of `parallel()` slots.

## Diffing manifests across a change

To pin down exactly what a refactor changed, capture a manifest before and after and diff them:

```ts
import {
  compareManifests,
  formatManifestDiff,
} from "@rangojs/router/__internal";

const oldManifest = await router.debugManifest();
// ... make changes ...
const newManifest = await router.debugManifest();

const diff = compareManifests(oldManifest, newManifest);
console.log(formatManifestDiff(diff));
```

`compareManifests` reports added, removed, and changed routes and layouts, with an old and new value per changed field. These helpers come from the `__internal` subpath — debugging utilities, not public API surface.

## Common issues

### A route sits under the wrong layout

Check that the `layout()` call wraps the route in its `use` callback (`layout(<Shell />, () => [path(...)])`). A `path()` listed next to a `layout()` is a sibling, not a child. See [Layouts](/docs/rango/guides/layouts).

### Unexpected mount index

Each `.routes()` call (and the `urls` option) registers a separate mount (`M0`, `M1`, …), and each `include()` also takes a mount index. Routes registered by separate `.routes()` calls do not share layouts or middleware; compose modules with `include()` inside one `urls()` tree when they should.

### Missing flags

`hasMiddleware`, `hasLoader`, and `hasErrorBoundary` are per entry. Middleware or a loader declared on a parent layout shows on that layout, not on each child route.
