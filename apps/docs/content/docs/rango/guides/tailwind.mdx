You want Tailwind CSS v4 in your Rango app, with utility classes generated in dev and production and the stylesheet applied before first paint. The setup is four small steps: install, register the Vite plugin, create a CSS entry point, and link it in the Document with a `?url` import.

## Install

```bash
pnpm add -D tailwindcss @tailwindcss/vite
```

## Register the Vite plugin

```typescript
// vite.config.ts
import { defineConfig } from "vite";
import tailwindcss from "@tailwindcss/vite";
import { rango } from "@rangojs/router/vite";

export default defineConfig({
  plugins: [
    tailwindcss(),
    rango(),
    // ... other plugins
  ],
});
```

## Create the CSS entry point

```css
/* src/index.css */
@import "tailwindcss";
```

That single import is the whole entry point. Tailwind v4 does not need a `tailwind.config.js`, and the `@tailwindcss/vite` plugin handles content detection automatically — no `content` globs to maintain.

## Link it in the Document

Import the CSS file with `?url` to get a hashed URL, then preload and link it in `<head>`. Give the `<link rel="stylesheet">` a `precedence` prop so React 19 manages it as a resource — de-duped by `href`, ordered, and loaded before paint (no flash of unstyled content):

```tsx
// src/document.tsx
"use client";

import type { ReactNode } from "react";
import { MetaTags } from "@rangojs/router/client";
import styles from "./index.css?url";

export function Document({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <head>
        <link rel="preload" href={styles} as="style" precedence="default" />
        <link rel="stylesheet" href={styles} precedence="default" />
        <MetaTags />
      </head>
      <body className="font-sans antialiased text-slate-900 bg-slate-50">
        {children}
      </body>
    </html>
  );
}
```

The `?url` suffix tells Vite to return the processed CSS file's URL instead of injecting it as a side effect. This gives you a stable, hashed asset path that works in both development and production. The `<link rel="preload" as="style">` starts the stylesheet download early.

Use `?url` for the document stylesheet. A bare side-effect `import "./index.css"` also produces managed CSS via `@vitejs/plugin-rsc`, but it is not guaranteed to be in the initial streamed `<head>`. The [CSS guide](/docs/rango/guides/css) has the full reasoning.

## Customizing the theme

Tailwind v4 uses the CSS `@theme` block for customization — colors, fonts, breakpoints all live in your entry point:

```css
/* src/index.css */
@import "tailwindcss";

@theme {
  --font-sans: "Inter", system-ui, sans-serif;
  --color-primary: #3b82f6;
  --color-secondary: #64748b;
  --breakpoint-3xl: 1920px;
}
```

## Dark mode

Combine Tailwind with the Rango theme system (see the [Theme guide](/docs/rango/guides/theme)). With `attribute: "class"` (the default) the theme script puts `class="dark"` or `class="light"` on `<html>` before first paint; add `suppressHydrationWarning` to the Document's `<html>` so React accepts that change:

```typescript
export const router = createRouter({
  document: Document,
  urls: urlpatterns,
  theme: { attribute: "class" },
});
```

Tailwind v4's `dark:` variant follows `prefers-color-scheme` by default, so on its own it ignores the user's stored choice. Point it at the class instead:

```css
/* src/index.css */
@import "tailwindcss";
@custom-variant dark (&:where(.dark, .dark *));
```

Then use the `dark:` variant as usual:

```tsx
<div className="bg-white dark:bg-slate-900 text-slate-900 dark:text-white">
  Content
</div>
```

## Custom fonts

Use `@fontsource-variable` for self-hosted fonts bundled by Vite — the [Fonts guide](/docs/rango/guides/fonts) covers all the options:

```bash
pnpm add @fontsource-variable/inter
```

```css
/* src/index.css */
@import "@fontsource-variable/inter";
@import "tailwindcss";

@theme {
  --font-sans: "Inter Variable", system-ui, sans-serif;
}
```

No extra `<link>` tags needed in the Document — Vite bundles the font files from `node_modules` automatically.

## Multiple apps under a host router

If you run several apps under one [host router](/docs/rango/guides/host-router), you don't need to coordinate stylesheet `href`s or `precedence` values across them. A client-side navigation that crosses an app boundary is a **full document load**, not a soft swap — the server answers an app switch with `X-RSC-Reload` — so each app's document (stylesheets, theme, meta) is re-established by the target app's own load. That holds even though every app's `@import "tailwindcss"` can compile to the same hashed asset.

## Pitfalls

- **Classes not applied at all?** Check the `?url` import and the `<link>` in the Document — a bare side-effect CSS import is not guaranteed to be in the initial streamed `<head>`.
- **`dark:` classes follow the OS instead of the theme toggle?** Add `@custom-variant dark (&:where(.dark, .dark *));` to the CSS entry point.
- **Reaching for `tailwind.config.js`?** Tailwind v4 doesn't use it — put customization in the `@theme` block in CSS instead.
- **Missing `precedence` on the stylesheet link?** Without it, React doesn't manage the sheet — you lose dedup, ordering, and the before-paint load guarantee.
