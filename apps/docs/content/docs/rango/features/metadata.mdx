In most frameworks, metadata runs as a separate export and pays for its own data access. In Rango, metadata is a push at the point where the data already exists — a handler, a layout, or a loader calls `ctx.use(Meta)` and pushes descriptors:

```tsx
import { Meta } from "@rangojs/router";

// inside urls(({ path }) => [ ... ])
path(
  "/product/:slug",
  async (ctx) => {
    const product = await getProduct(ctx.params.slug);
    const meta = ctx.use(Meta);
    meta({ title: product.name });
    meta({ property: "og:image", content: product.image });
    return <ProductPage product={product} />;
  },
  { name: "product" },
);
```

The collected tags render wherever you place `<MetaTags />` from `@rangojs/router/client` — normally inside `<head>` in your document:

```tsx
import type { ReactNode } from "react";
import { MetaTags } from "@rangojs/router/client";

export function Document({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <head>
        <MetaTags />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

## Segments layer

A layout sets a template, the route pushes a value, and the collected head composes them:

<MetaLayersDemo />

Later segments override earlier ones per key (`title`, `name`, `property`, …), an `{ unset: key }` descriptor removes an inherited tag, and a layout can set a title template that later titles fill in (`meta({ title: { template: "%s — Shop", default: "Shop" } })`). Deferred (Promise) values resolve before collection, so async metadata participates in templating like any other value. On soft navigation the previous title holds until the new one resolves — no flash of an intermediate state.

Loaders can push metadata too, which keeps a data-derived title next to the fetch. Loader pushes stream, so one that settles late is applied after hydration rather than in the server HTML; register the loader with `{ ssr: false }` when the tag must be in the first response (see [Loaders](/docs/rango/features/loaders#loaders-can-write-handles)).

## Meta is not a special case

`Meta` is one instance of the **handle** primitive. `createHandle()` gives any feature the same contract: push data from handlers (or loaders) in segment order, define a collect function, read the result with `useHandle()` on the client.

```tsx
// handles/rendered-products.ts
import { createHandle } from "@rangojs/router";

// one push per product id, collected into a flat string[]
export const RenderedProducts = createHandle<string, string[]>((segments) =>
  segments.flat(),
);

// in a handler: each segment pushes what it rendered
const track = ctx.use(RenderedProducts);
for (const p of products) track(p.id);

// in a client component (useHandle from @rangojs/router/client)
const ids = useHandle(RenderedProducts);
```

Without a collect function, a handle returns one array per segment that pushed (`T[][]`), in segment order. `Script` (nonced script injection) and `Breadcrumbs` are the other built-ins; your own accumulate-across-segments needs ride the same mechanism. See [Breadcrumbs](/docs/rango/guides/breadcrumbs) and [Scripts](/docs/rango/guides/scripts).

## Handles replay on cache hits

Handles are captured when a segment renders and **replayed on every cache or prerender hit**. That replay is a typed channel from the frozen half of a render to the live half: the cached artifact can describe itself, and loaders — always live — can read that description.

The canonical case is the `RenderedProducts` handle above: a prerendered product list tracks which product ids it rendered; a live price loader awaits `ctx.rendered()`, reads the replayed handle with `ctx.get(RenderedProducts)`, and fetches prices for exactly those products in one batched query. The holes can never desync from the shell — the live data always matches what is actually displayed, by construction — and the dynamic data is batched instead of fetched per-hole. Only pushes from the frozen render (handlers) are part of the replayed artifact; a loader push is request-time. See [Shell Manifest](/docs/rango/guides/shell-manifest) for the full pattern.
