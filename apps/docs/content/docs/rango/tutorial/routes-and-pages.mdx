## Two new routes

Add the shop grid and the product page to the tree. `:slug` in a pattern is a URL parameter — whatever matches that segment shows up in the handler as `ctx.params.slug`:

```tsx
// src/urls.tsx
import { urls } from "@rangojs/router";
import { HomePage } from "./pages/home";
import { ProductPage } from "./pages/product";
import { ShopPage } from "./pages/shop";

export const urlpatterns = urls(({ path }) => [
  path("/", HomePage, { name: "home" }),
  path("/shop", ShopPage, { name: "shop" }),
  path("/shop/:slug", ProductPage, { name: "product" }),
]);
```

Every route gets a name (`home`, `shop`, `product`). Names are how you refer to routes from now on, both for typed handlers and for building URLs.

## Route types

Route names carry their param types. The Vite plugin reads your route tree and writes `src/router.named-routes.gen.ts`, a map of every route name to its pattern: when the dev server starts, again whenever a route file changes, and on every build. With that map in place, `Handler<"product">` resolves automatically: the compiler knows that route has a `slug` param and types `ctx.params` accordingly.

To write the route types without starting Vite (on a fresh clone, or before a CI typecheck), run the CLI:

```bash
pnpm exec rango generate src/
```

Besides the router-level map, the CLI writes a per-module `urls.gen.ts` next to `urls.tsx`, which client components use with `useReverse()`. The Vite plugin never writes per-module files, so re-run the command when a `path()` changes, or let a `predev` script do it before every `pnpm dev`:

```jsonc
// package.json (scripts section)
{
  "scripts": {
    "predev": "rango generate src",
    "dev": "vite",
  },
}
```

Commit the `.gen.ts` files, and never edit them by hand.

## The shop grid

```tsx
// src/pages/shop.tsx
import type { Handler } from "@rangojs/router";
import { PRODUCTS } from "../data";

export const ShopPage: Handler<"shop"> = (ctx) => {
  return (
    <section>
      <h1>Shop</h1>
      <ul>
        {PRODUCTS.map((product) => (
          <li key={product.slug}>
            <a href={ctx.reverse("product", { slug: product.slug })}>
              {product.name} — ${product.price}
            </a>
          </li>
        ))}
      </ul>
    </section>
  );
};
```

The interesting line is `ctx.reverse("product", { slug: product.slug })`. Instead of hardcoding `/shop/${product.slug}`, you ask the router to build the URL from the route's name, like Django's `reverse()`. If the pattern ever changes in `urls.tsx`, every generated URL follows, and a misspelled name or a missing param is a type error.

Plain `<a>` tags mean full page loads for now. Part 3 upgrades these to client-side navigation.

## The product page

```tsx
// src/pages/product.tsx
import { notFound } from "@rangojs/router";
import type { Handler } from "@rangojs/router";
import { PRODUCTS } from "../data";

export const ProductPage: Handler<"product"> = (ctx) => {
  const product = PRODUCTS.find((p) => p.slug === ctx.params.slug);
  if (!product) notFound(`No product called "${ctx.params.slug}"`);

  return (
    <article>
      <h1>{product.name}</h1>
      <p>{product.description}</p>
      <p>${product.price}</p>
    </article>
  );
};
```

Two things to notice:

- `ctx.params.slug` is a typed `string`. That's `Handler<"product">` doing its job from the generated route map.
- `notFound()` covers the case where the route _matched_ but the data doesn't exist: `/shop/decaf-pods` fits the `/shop/:slug` pattern, yet there's no such product. Calling `notFound()` stops the handler and responds with HTTP 404 and a built-in not-found page. It returns `never`, so TypeScript knows `product` is defined on the lines after it. When no route matches at all (say, `/warehouse`), the router 404s on its own without any code from you. Both fallbacks are customizable. See [Routing](/docs/rango/features/routing) when you want branded 404 pages.

## Point the home page at the shop

`ctx.reverse()` works in any handler, so give the landing page a real link:

```tsx
// src/pages/home.tsx
import type { Handler } from "@rangojs/router";

export const HomePage: Handler<"home"> = (ctx) => (
  <section>
    <h1>Brew</h1>
    <p>Gear for better coffee.</p>
    <a href={ctx.reverse("shop")}>Browse the shop</a>
  </section>
);
```

## Try it

Run `pnpm dev` and click around: `/` links to `/shop`, the grid links to each product, and a made-up slug like `/shop/decaf-pods` returns a 404. Three routes, all typed, all addressable by name.
